**现有链路（已跑通的部分）**
```
车机 ──Wi-Fi── UniFi 路由器
   └─ DNS 劫持：snc-api-gw.zeekrlife.com / snc-download-cdn.zeekrlife.com → Mac 192.168.8.8
        └─ Mac 0.0.0.0:443 = lan_sideload.py 的 SNI 分流器
             └─ HTTP CONNECT → mitmdump (regular, 127.0.0.1:18081, --emudhra)
                  └─ addons/zeekr_log.py：注入元数据「有更新」+ 替换 .apk 下载内容 + 改写 /app/signature 响应
```
- 解密靠 **eMudhra 中间 CA 私钥泄露**（mitmproxy `--emudhra` 的链，车机仍信任）→ 车上**不需要装证书**。
- 商店下载链路：`v1/app/appList`（上报已安装包）、`v1/app/detail/app/<id>`、`v2/app/signature`（鉴权）、CDN `GET .../*.apk`（Range 下载）。

**已确认的机制（今天的抓包证据）**
1. 注入生效、下载替换生效（`Content-Range …/19,042,758` = DiPlay 真实大小，官方包是 231,623,624 B）。
2. 一轮下载里商店查**两次**签名：
   - `sign(packageName=com.zeekr.media.qq, apkVersion=<我们注入的假高版本>, sha256=7d04db26…)` ← 元数据身份
   - `sign(packageName=com.shihab.diplay, apkVersion=41, sha256=7d04db26…)` ← **APK 文件自身的身份**（41 = DiPlay 0.2.22 真实 versionCode，apktool 核对过）
   - 两者都返回 `sign:null` → 安装被拒。
3. 服务端**只按 sha256 认官方内容**：官方哈希→344 字符真签名；任何第三方哈希→`sign:null`。同一包同版本 A/B 已验证。
4. 签名响应只有 `{"sign":…,"signType":0}`，**不回显绑定字段** → 客户端要认只能本地验签。
5. **网关 API 签名可原样重放**：旧 `x-timestamp`、旧 nonce 原样重放仍 200；改 body 或改 timestamp 立刻 `00A06`（签名覆盖 path+body+ts，但**无时效窗、无 nonce 去重**）。
6. **下载 CDN 完全不鉴权**（无 token，只需 `Range` + `Host`）→ Mac 上可 Range 直读商店任意 APK。
7. 浏览器 `com.zeekr.broswer` 路线已排除：它的 manifest **没有 `REQUEST_INSTALL_PACKAGES`**，6 个 dex 里也搜不到「商城以外 / 无法安装 / 未知来源」→ 那句提示来自**商店本体或车机系统层**（尚未分辨，需要用户确认是哪个界面弹的）。

**推断（未证实）**：5.6d 的安装授权认的是「**这个包是不是商店的应用**」，所以单靠下载替换不够，必须让 **APK 文件自身**也像商店应用（换壳），可能还要配合伪造 `sign` 响应。

## What was tried

- **只替换下载内容、不改元数据** → 商店下载阶段哈希校验失败（上游记录，本车同理）

## Decisions

- **主线改成 E7 换壳**：让下载回来的 APK 自身身份也像商店应用（改包名 → 自签），而不是只跟 `sign` 较劲 —— 因为本车提示针对的是「应用身份」
- **签名伪造并行推进**（E1/E2/E4）：便宜，且能分辨门到底是「sign 非空」「本地验签但不绑哈希」还是「验签且绑哈希」
- **换壳只改包名、不改类名**，并把相对组件名先展开为绝对名，再跑 dex 组件校验 —— 避免换壳后 ClassNotFound
- **优先挑「商店收录但车上未装」的包名**做壳（无签名冲突）；退路是「卸载 QQ音乐（`supportUninstall:1`）→ 以全新安装身份装换壳包」
- **E6（`launcherActivities` 组件劫持）保持平行尝试**：5.6d 上若能拉起系统设置/工程模式并开 **ADB 或"允许安装未知应用"**，就直接结束战斗，比绕签名彻底
- **不在车上装证书 / 不改系统**：保持"退出即恢复、失败可回滚"
- 一切结论必须引用 `logs/` 里的原始记录或命令输出
